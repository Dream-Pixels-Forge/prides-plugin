# Prototype Phase Rules

## PRD Structure
- Executive Summary (goals, audience, metrics)
- Functional Requirements (user stories, use cases, edge cases)
- Non-Functional Requirements (performance, security, accessibility)
- Technical Specifications (APIs, data models, integrations)
- Acceptance Criteria (success conditions, test scenarios)

## Writing Standards
- Use clear, unambiguous language
- Number requirements for traceability
- Priority labels: Must have / Should have / Could have
- Include visual diagrams where helpful

## User Story Format
```
As a [role]
I want [feature]
So that [benefit]
```

## Definition of Done
- [ ] All requirements have acceptance criteria
- [ ] Edge cases documented
- [ ] Non-functional requirements specified
- [ ] Scope boundaries defined (what's NOT included)
- [ ] Dependencies identified

## Anti-Patterns
- Vague requirements ("should be fast")
- Missing edge cases
- No success metrics
- Scope creep without documentation
